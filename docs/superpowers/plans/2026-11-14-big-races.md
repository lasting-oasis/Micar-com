# Big Races Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task, in your own session (the trial rules: the boss is the independent reviewer). Steps use checkbox (`- [ ]`) syntax for tracking. Read `docs/superpowers/plans/2026-11-13-trial-rules.md` first: its rules apply to every task here.

**Goal:** Races of 4, 8, 12 or 16 cars on the Strip's circuits: by invite link (Part 1), by quick race with strangers (Part 2), and with computer drivers in the empty places (Part 3).

**Architecture:** The room's size is lane A's `Room.max`, chosen by the host from 4/8/12/16 up to the server's ceiling (`RACE_ROOM_MAX`), which the page reads from `/api/caps`. A pure `gridPlace` puts sixteen cars behind every start line. On the page, the other cars of a race are one instanced field (six draw calls for all fifteen) and their numbers and names are drawn on the HUD canvas. The server keeps relaying poses as today with fewer bytes each, and sends a page that asks one batch of poses per tick. Quick rooms are ordinary rooms the server finds or opens per circuit and starts by itself; computer drivers are stepped on the server with the solo races' own `stepAI` and relayed like people.

**Tech Stack:** apps/sim: TypeScript, React 18, three 0.160, socket.io 4.8, vitest 2.1, Playwright (smokes), tsx. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-14-big-races-design.md`

1. **A link or a page from before this work** (no size sent; a room of 4 joined from an old link) → on the live server (ceiling 4) a room of 4, the grid, colours and lobby exactly as today → Task 1 tests "a page that sends no size gets the largest room the server makes" and "a server without RACE_ROOM_MAX", Task 4 smoke's four-person check.

5. **The ceiling is 4 on the live server** → no size picker, no change on screen, a room of 8 refused if asked by hand → Task 1 wiring test "a server without RACE_ROOM_MAX".

### Task 2: Sixteen grid places on every circuit

**Files:**
- Create: `apps/sim/src/world/strip/grid.ts`

**Interfaces:**
- Produces, in `grid.ts`: `GRID_PLACES = 16`, `GRID_ROW_M = 8`, `GRID_LANE_M = 3`; `type GridPlace = { x: number; z: number; h: number; s: number }`; `gridPlace(eventId: string, slot: number): GridPlace` — metres, the car's heading (radians, `Vehicle.h`'s convention) and the place's distance along the event's route (a lap race: −8 per row behind the line; a route that begins at the line: 0). `slot` is clamped to a whole number 0..15; a slot that is not a finite number is 0.
- The rule (measured on all eighteen non-drag events: the spec's "The grid"): row r = ⌊slot/2⌋ stands 8r m behind the event's start point along the circuit's closed centre line (`zoneRoads` of the track: the start point lies on it), the even slot 3 m to the left, the odd 3 m to the right of that point (left = −(−tz, tx), as `EventRunner.start`'s `right`), facing that point's tangent. Every place of a race of people follows this rule, the first four included.
- `EventRunner.start` for a race of people (non-drag) puts the player at `gridPlace(ev.id, net.slot)` with that place's heading and its `s` as `pS`/`pMax`, and each other person at `gridPlace(ev.id, o.slot)` with its heading and `s`. A solo race keeps its four slots and its random place. A drag is unchanged.
