# One Bay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One bay screen in MiCar World where a car's repairs, body work and parts are chosen together and paid as one work order, with the MiCar Tuner configurator's bolt-on parts on all seven body styles.

**Architecture:** Every fault and every part names a slot of the car in a pure catalogue (`apps/sim/src/bay/`) that the server and the client both import. One socket message, `bay_order`, prices and applies a mixed order against the records that exist today: faults on the car, the build in the Strip record. The new parts are geometry placed from each lofted body's own measurements, and the bay screen is the configurator's layout over the Garage's turntable.

**Tech Stack:** TypeScript 5.9.3, React 18.3.1, three 0.160.1, zustand 4.5.7, socket.io 4.8.3, Tailwind 3.4.19, vitest 2.1.9, Playwright 1.63.0. All are already in `apps/sim`.

**Spec:** `docs/superpowers/specs/2026-11-11-one-bay-design.md`. Read it first: the slot table (4.1), the new parts (4.3) and the order rules (4.4) are argued there and only summarised here.

Both documents were written on 2026-11-11 and are kept in the Micar App project as `claude/micar-one-bay-design.md` and `claude/micar-one-bay-plan.md`. They were added to the repository at the end of Stage 1, on `one-bay-1`. **Stage 1 (Tasks 1 to 5) is built. Read "Stage 1 as built" at the end of this plan before starting any later task:** it lists what differs from the task text below and what later tasks must know.

## Global Constraints

- No dependency is added or upgraded.
- The sim draws at 2 world units per metre (`WORLD_PER_M`). Lofted bodies face −Z.
- The bay charges dollars (`player.money`) only. Octane (`player.octane`) is not spent here.
- Nothing in the world writes a grade, a passport event or a card's condition. `packages/engine` is not modified.
- No part changes how a car drives. `PerfCfg`, `Tune`, `carParams` and `world/physics.ts` are not touched.
- Every existing price, repair cost, repair impact and star rating is unchanged. A repair fails 15% of the time without a Master Mechanic and never with one. A Master Mechanic takes 20% off repairs.
- A save made before this change loads. New fields are optional or defaulted. There is no migration script.
- A rental stays stock. A visitor acts only on a car they own.
- Brand: windshield yellow `#ffd23f` on night `#0e1217`, Barlow and Barlow Condensed, through the Tailwind tokens already in use (`bg-background`, `text-ink`, `text-haze`, `bg-market`, `text-market`, `border-line`, `font-cond`). Touch targets are `min-h-[44px]`.
- The bay's own labels are in English and Spanish through `src/i18n.tsx`. Catalogue names stay English, as the Garage's are today.
- At the end of every task `pnpm --filter @micar/sim test` passes and `pnpm --filter @micar/sim build` passes (`tsc --noEmit && vite build`; `noUnusedLocals` and `noUnusedParameters` are on). Run the suite before Task 1 and take that count as the baseline: it was 362 on `c600d5b`, the commit this plan was written against, and `main` has moved since (see "Checked while writing this plan").
- Each stage is one branch (`one-bay-1` to `one-bay-4`), merged to `main` after its gate. Socket messages that have a sender today keep working until Task 16.
- Git commands run from the repository root. Commit or push only what the task names.
- Commit messages follow the repo: `area: what is now true`.

### Task 2: Every lost point has a fault

**Files:**
- Create: `src/bay/faults.ts`
- Test: `src/bay/faults.test.ts`

**Interfaces:**
- Consumes: Task 1; `type Car`, `type RepairDef` from `src/types.ts`.
- Produces:
  - `type CarSheet = { mechanical: number; body: number; slots: Record<SlotId, { slot: SlotId; condition: number; faults: RepairDef[] }> }`
  - `carSheet(car: Pick<Car, 'bodyCondition' | 'mechanicCondition' | 'activeRepairs'>): CarSheet`. `mechanical` and `body` are the car's two scores, rounded. A slot's `condition` is 100 less the impact of its open faults, never below 0.
  - `explainCondition(car: Car, rng: () => number, id: () => string): RepairDef[]`. Adds faults to `car.activeRepairs` until each trade's lost points are covered, and returns the ones added.

- [ ] **Step 1: Write the failing tests.** `fault` goes in `src/bay/testing.ts`, which the later test files share.

```ts
const fault = (id: string, partName: string, impact?: number): RepairDef => { const j = repairJobFor(partName)!; return { id, name: j.n, partName, type: j.trade, cost: j.cost, conditionImpact: impact ?? j.impact }; };
const car = (body: number, mech: number, faults: RepairDef[] = []) => ({ id: 'c1', bodyCondition: body, mechanicCondition: mech, condition: Math.floor((body + mech) / 2), activeRepairs: faults }) as Car;
const ids = () => { let n = 0; return () => 'rep-t-' + ++n; };
const lost = (fs: RepairDef[]) => fs.reduce((s, f) => s + f.conditionImpact, 0);

it('a trade-in at 60 body with no faults gets body faults worth exactly 40', () => { const c = car(60, 100), added = explainCondition(c, () => 0, ids()); expect(lost(added)).toBe(40); expect(added.every(f => f.type === 'body' && repairJobFor(f.partName)?.trade === 'body')).toBe(true); expect(c.activeRepairs).toEqual(added); expect(new Set(added.map(f => f.id)).size).toBe(added.length); });
it('adds nothing twice, and nothing when the faults already cover the loss', () => { const c = car(60, 100); explainCondition(c, () => 0, ids()); expect(explainCondition(c, () => 0.99, ids())).toEqual([]); const over = car(0, 100, [fault('a', 'Frame Pulling Service'), fault('b', 'Frame Pulling Service'), fault('c', 'Frame Pulling Service')]); expect(explainCondition(over, () => 0, ids())).toEqual([]); });
it('adds only the unexplained part, to the trade that lost it', () => { const c = car(100, 73, [fault('a', 'Brake Pad Set')]), added = explainCondition(c, () => 0.5, ids()); expect(lost(added)).toBe(17); expect(added.every(f => f.type === 'mechanic')).toBe(true); });
it('a gap smaller than any fault becomes the smallest fault at that size, at its full price', () => { const added = explainCondition(car(97, 100), () => 0, ids()); expect(added.length).toBe(1); expect(added[0].conditionImpact).toBe(3); expect(added[0].cost).toBe(repairJobFor(added[0].partName)!.cost); });
it('a car saved with no fault list and a score that is not a whole number is handled', () => { const c = { id: 'c2', bodyCondition: 59.6, mechanicCondition: 100, condition: 79 } as Car; expect(lost(explainCondition(c, () => 0, ids()))).toBe(40); });
```

- [ ] **Step 2: Run to verify they fail.** `pnpm --filter @micar/sim exec vitest run src/bay/faults.test.ts`. Expected: FAIL, cannot resolve `./faults`.

- [ ] **Step 3: Implement `carSheet` and `explainCondition`.** The tests do not fix the choice of faults, so this is the algorithm. For each trade: `gap = (100 − round(score)) − (impact of the trade's listed faults)`. While `gap > 0`: take the trade's jobs with `impact <= gap` whose part name is not already on the car; if there are any, pick `candidates[floor(rng() × candidates.length)]` and add it at its own impact; if there are none, add the trade's first job with the smallest impact, with `conditionImpact = gap`. Subtract what was added. Stop after 8 faults per trade. A missing `activeRepairs` is treated as empty and created.

**Files:**

- Produces:

  - `type WorkOrder = OrderResult & { id: string; carId: string; car: string; door: Door; day: number }`
